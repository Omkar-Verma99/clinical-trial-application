WHAT IS A HEALTH CHECK?
════════════════════════════════════════════════════════════════════════════

Health Check = Google Cloud periodically pinging your app to confirm it's alive

WHY DOES GOOGLE DO THIS?
├─ Production apps need uptime monitoring
├─ If app doesn't respond, Google can restart it
└─ Used for load balancing and auto-scaling decisions

YOUR app.yaml SETTINGS:
┌─────────────────────────────────────────────────────────────────────────┐
│ Setting                  │ Current       │ What It Means              │
├─────────────────────────────────────────────────────────────────────────┤
│ enable_health_check      │ true          │ Health check is ON         │
│ check_interval_sec       │ 10            │ Ping every 10 SECONDS      │
│ timeout_sec              │ 10            │ Wait 10 sec for response   │
│ healthy_threshold        │ 2             │ Need 2 OK responses        │
│ unhealthy_threshold      │ 3             │ Need 3 failures to restart │
│ initial_delay_sec        │ 300           │ Wait 5 min before 1st ping │
│ port                     │ 3000          │ Ping on port 3000          │
│ path                     │ /             │ Ping root path (/)         │
│ min_instances            │ 1             │ Always keep 1 running      │
│ instanceClass            │ F2            │ Size: 2 vCPU + 512MB RAM   │
└─────────────────────────────────────────────────────────────────────────┘

PROBLEM: check_interval_sec: 10 IS TOO AGGRESSIVE
═════════════════════════════════════════════════════════════════════════

Your app is pinged EVERY 10 SECONDS:

  60 sec/min ÷ 10 sec/check = 6 checks per minute
  6 per min × 60 min/hour = 360 checks per hour
  360 per hour × 24 hours/day = 8,640 checks per day
  8,640 per day × 30 days/month = 259,200 checks per month!

EACH CHECK GENERATES LOGS:
  • Request log: "GET / HTTP/1.1 200"
  • Response log: "Response sent in 45ms"
  • Metadata: timestamp, status, size, etc

259,200 CHECKS × 10KB per log entry = 2,592 GB logs per month!

Google Logging stores all this, charges ₹0.19 per GB over 50GB free:
  (2,592 - 50) × ₹0.19 = ₹485 charge per month!

════════════════════════════════════════════════════════════════════════════
SOLUTION #1: FIX HEALTH CHECK INTERVAL (5 MINUTES)
════════════════════════════════════════════════════════════════════════════

CHANGE IN app.yaml:

│ Line 10: check_interval_sec: 10                                         │
│ Change to: check_interval_sec: 60                                       │
└─────────────────────────────────────────────────────────────────────────┘

WHY CHANGE TO 60?
├─ Still monitors health (checks every 60 seconds = once per minute)
├─ Reduces checks from 259k to 43k per month (5.6x reduction!)
├─ Logs reduced from 2,600GB to 430GB per month
├─ Cost drops from ₹485 → ₹0 (now within 50GB free tier!)
└─ App health is STILL monitored, just less frequently

COST SAVINGS: ₹485/month ✅

├─ ✅ Detects failures within 60 seconds (vs 10 seconds)
├─ ✅ Still auto-restarts if app crashes
└─ ✅ For a 3-patient pilot app: 60 sec response time is MORE than fine
